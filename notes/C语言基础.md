## 1.1 volatile

`volatile` 告诉编译器：**这个对象的值可能在编译器看不到的地方被改变，因此每次使用都必须重新从内存读取，每次写入都必须真的落盘，不许用寄存器缓存、不许做常量传播、不许删除"看起来没用"的访问。**

**典型场景**
[1]外设寄存器由硬件改变
[2]中断服务函数与主循环共享的变量
[3]DMA缓冲区
[4]RTOS中跨任务共享的标志 

- **"volatile 和 const 能一起用吗？"** 能，且有意义：只读的状态寄存器 `const volatile uint32_t *STATUS`——程序不许写，但硬件会改。
- **"volatile 保证原子性吗？/加了volatile就能保证内存访问顺序吗？"**  不能，volatile **不保证原子性**，它恰恰产生多条独立的 load/store（LDR/STR）。`count++` 仍是读-改-写三步。
- **"给所有变量都加volatile可行吗？"** 不行，丧失了常见优化（如给局部变量加很明显是没意义的），只需要给外部会修改的地方加
## 1.2 static
`static` 有两个作用：在文件作用域修饰变量和函数时，把外部链接改为内部链接，让它们只在本编译单元可见，避免命名冲突并允许编译器内联删除；在函数内修饰局部变量时，把自动存储期改为静态存储期，放进 .data/.bss，程序启动时初始化一次，函数返回后仍保留。它不减少 RAM 占用，也不提供线程安全。

**典型场景**
[1]模块私有化->防止符号冲突/编译单元内联/接口收敛
[2]保持状态（函数内定义只初始化一次）
[3]单次初始化状态机

- **"static 局部变量和普通局部变量的区别？"** 普通局部变量在栈上、每次调用重新创建、函数返回即销毁；**静态存储对象在程序加载/启动时就完成初始化，不参与运行期的重复初始化**。static 局部变量在 `.data`/`.bss`、程序启动时初始化一次、函数返回后仍保留、生命周期到程序结束。
- **"static 修改变量时，能减少内存占用吗？**" 不能，反而可能增加（`.data` 同时占 RAM 和 Flash）。**想省 RAM 要用 `const` 放到 `.rodata`（Flash）**。
-  **"static 和 extern 能一起用吗？"** 不能，语义矛盾，编译器报错。
- **"头文件里能不能定义 static 变量？"** 能编译，但**每个包含它的编译单元各生成一份独立副本**，不是共享的「全局变量」。头文件里放 `extern` 声明，定义放在唯一的 .c 文件里,此时变量成为唯一共享的全局变量

## 1.3 # 和 ## 用法

`#` 和 `##`都只能出现在带参数的宏定义中，发生在**预处理阶段**

### 1.3.1 ‘#’
`#`把宏参数原样转换成字符串字面量，常用于日志/断言
```c
#define PRINT_EXPR(x)  printf("%s = %d\n", #x, (x))

int a = 10;
PRINT_EXPR(a + 1);     // 输出：a + 1 = 11
```
### 1.3.2 ‘##’
`##` 把左右两个预处理标记拼成一个新的标记，可用于批量生成变量名、函数名或寄存器名。
```c
#define CONCAT(a, b)   a ## b
#define GPIO_PORT(n)   GPIO ## n

int CONCAT(value, 1) = 100;  // 等价于 int value1 = 100;
GPIO_PORT(A)->ODR = 0;       // 等价于 GPIOA->ODR = 0;
```

### 1.4 `const` 指针、常量指针、指针数组与数组指针

```c
const int *p1 = &a;        // 常量指针：p1 可改指向，不能通过 p1 改 *p1
int * const p2 = &a;       // 指针常量：p2 不能改指向，可以通过 p2 改 *p2
const int * const p3 = &a; // 常量指针常量：指向和数据都不能通过 p3 修改
```

### 1.5指针数组与数组指针

`[]` 的优先级高于 `*`，因此：

```c
int *p[4];    // 指针数组：p 是数组，含 4 个 int * 元素
int (*q)[4];  // 数组指针：q 是指针，指向一个 int[4] 数组
```

### 1.6 `sizeof` 和 `strlen` 的区别

| 对比项  | `sizeof`     | `strlen`              |
| ---- | ------------ | --------------------- |
| 本质   | 运算符，不是函数     | C库函数，需包含 `<string.h>` |
| 计算内容 | 类型或对象占用的字节数  | 字符串中 `\0` 前的字符数       |
| 参数   | 类型或表达式       | 指向以 `\0` 结尾字符序列的指针    |
| 计算时机 | 普通对象通常编译期可确定 | 运行时逐字节查找 `\0`         |
| 返回类型 | `size_t`     | `size_t`              |

```c
char str[20] = "0123456789";

sizeof(str);  // 20：整个数组占用20字节，包含未使用空间和结尾\0
strlen(str);  // 10：只统计\0前的有效字符
```

- `strlen` 只适用于有 `\0` 结尾的字符串；未终止的字符数组调用它会越界读取，行为未定义。
- `sizeof` 不会得到动态分配内存的大小：`malloc(100)` 返回指针，`sizeof(ptr)` 仍只是指针大小。
### 1.7 堆栈

| 对比项  | 栈               | 堆                    |
| ---- | --------------- | -------------------- |
| 分配方式 | 编译器按函数调用自动分配/释放 | 程序运行时主动申请和释放         |
| 生命周期 | 离开作用域或函数返回即结束   | 从申请成功到 `free/delete` |
| 速度   | 通常快，只需移动栈指针     | 较慢，需要查找和维护空闲块        |
| 大小   | 通常较小且固定，例如任务栈   | 可用空间较大，但可能碎片化        |
| 常见风险 | 栈溢出、返回局部变量地址    | 内存泄漏、碎片、野指针、重复释放     |
> 面试概述：栈适合生命周期明确、大小较小的临时数据，自动管理；堆适合运行时才能确定大小或生命周期的数据，但必须自己管理释放。在FreeRTOS中，每个任务还有独立任务栈，栈大小不足会引发任务栈溢出。

#### 内存泄漏？

简单地说就是申请了一块内存空间，使用完毕后没有释放掉。 它的一般表现方式是程序运行时间越长，占用内存越多，最终用尽全部内存，整个系统崩溃。由程序申 请的一块内存，且没有任何一个指针指向它，那么这块内存就泄露了。
### 1.8 函数指针和指针函数

```c
int (*fp)(int);  // 函数指针：fp是指针，指向“参数int、返回int”的函数
int *func(int);  // 指针函数：func是函数，返回值类型是int *
```
#### `p`、`*p` 和 `&p`

```c
int a = 10;
int *p = &a;
```

| 表达式  | 含义                              |
| ---- | ------------------------------- |
| `p`  | 指针变量，保存 `a` 的地址，即 `p == &a`     |
| `*p` | 解引用：取出 `p` 指向地址中的数据，即 `*p == a` |
| `&p` | 取地址：得到指针变量 `p` 自己的地址            |
|      |                                 |
